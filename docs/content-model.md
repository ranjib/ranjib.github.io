# Content Model

Public posts use a small, stable frontmatter contract:

```yaml
title: "Post Title"
date: 2026-08-13T00:00:00-07:00
draft: false
description: "Search and social snippet under 160 characters."
summary: "Plain card and listing copy for readers."
lane: "engineering-ai"
tags:
  - "context engineering"
featured: false
images:
  - "images/social/default-card.png"
image_alt: "Ranjib Dey social preview"
```

## Lanes

Every published post needs exactly one primary `lane`.

Allowed lane values:

- `engineering-ai`: Engineering & AI
- `open-source-making`: Open Source & Making
- `field-notes`: Field Notes
- `learning-life`: Learning & Life

Add or rename lanes only by updating all of these together:

- `data/lanes.toml`
- `content/lanes/*/_index.md`
- existing post frontmatter
- any homepage or Start Here links that point at the lane

`learning-life` is for public-safe learning and reflection. Do not use it for family logistics, child-identifying details, health records, precise home information, relationship details, or private knowledge-graph material.

## Tags

Use focused, reusable tags. Prefer stable topic names such as `context engineering`, `reliability`, `reef-pi`, `open source`, and `field planning`.

Do not create one-off tags unless a future reader would reasonably browse by that topic.

## Summaries

`description` is for metadata and should stay concise. `summary` is reader-facing card copy and must be plain text so listing pages emit valid HTML.

The post card partial intentionally reads `summary` first and falls back to a plainified Hugo summary only when needed.

## Related Reading

Related reading is driven by Hugo's related-content configuration in `config.toml`. Shared `lane` has the highest weight, followed by shared `tags`, then date proximity. Article pages show up to four related posts and exclude the current post.

## Approved Photo Suggestions

Photo suggestions are generated by the private `llm-wiki-ranjib` knowledge graph
and consumed here only after review. This repo must not read private
`raw/local/photos` inventories, cluster manifests, face labels, or unapproved
candidate files directly.

Website-side approved suggestion files live at:

```text
data/photo-suggestions/<post-slug>.json
```

The filename slug must match a published post at `content/posts/<post-slug>.md`.
Each suggestion must reference an already-exported image under:

```text
assets/images/posts/<post-slug>/<public-photo-id>.jpg
```

Suggestion manifests use this shape:

```json
{
  "generator_version": "photo-blog-publishing-v1",
  "generated_at": "2026-08-24T00:00:00Z",
  "source_repo": "llm-wiki-ranjib",
  "post_slug": "planning-overlanding-trips-like-reliability-reviews",
  "photos": [
    {
      "public_photo_id": "photo-planning-overlanding-trips-like-reliability-reviews-abc123",
      "image_path": "images/posts/planning-overlanding-trips-like-reliability-reviews/photo-planning-overlanding-trips-like-reliability-reviews-abc123.jpg",
      "alt": "Public-safe alt text approved in the KG review.",
      "caption": "Public-safe caption approved in the KG review.",
      "kg_source": "llm-wiki-ranjib:photo-planning-overlanding-trips-like-reliability-reviews-abc123",
      "source_cluster_id": "gps-example",
      "reasons": ["tag:overlanding"]
    }
  ]
}
```

Required fields:

- `generator_version`: must be `photo-blog-publishing-v1`.
- `post_slug`: must match the suggestion filename and an existing post.
- `public_photo_id`: stable public KG photo ID.
- `image_path`: path relative to `assets/`, starting with
  `images/posts/<post-slug>/`.
- `alt`: approved public alt text.
- `caption`: approved public caption.
- `kg_source`: public provenance ID beginning with `llm-wiki-ranjib:`.

Run `node scripts/validate-content-model.mjs public` after building the site.
Validation fails if a suggestion references a missing image, has an invalid post
slug, lacks alt text or caption, or points outside the post image directory.
